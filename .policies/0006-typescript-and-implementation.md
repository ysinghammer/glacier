# 0006 — TypeScript and implementation

1. Standalone behavior MUST use classes, including use cases/factories; utilities MUST use static methods on purpose-specific classes, not global utility containers. Stateless behavior MUST NOT require artificial state. Plain records, interfaces, and aliases MAY describe data; behaviorless classes MUST NOT be manufactured merely to hold it.
2. Functions MUST be limited to framework/platform-required entry points and callbacks, including React components/hooks/React-required callbacks. Callbacks MUST remain focused and delegate substantial behavior to named methods; this exception MUST NOT convert unrelated standalone behavior into functions.
3. Code MUST prioritize readable explicit control flow over clever expressions, compressed statements, nested ternaries, and abstractions merely reducing line count. Methods/files MUST have cohesive responsibilities; guard clauses MUST be used where clearer. Arbitrary line-count/complexity limits are not prescribed. Bindings MUST default to `const`, use `let` only for reassignment, and MUST NOT use `var`. Nonmutating contracts MUST use readonly members/collections; runtime-private class state MUST use native `#private`.
4. Speculative abstractions, dead code, unexplained magic values, and accidental import-time effects MUST NOT be introduced. Named constants MUST explain meaningful fixed values; reuse MUST respect semantic ownership.
5. Compiler configuration MUST enable `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noUnusedLocals`, `noUnusedParameters`, and `noFallthroughCasesInSwitch`. Current `tsconfig.base.json` also enables `verbatimModuleSyntax` and `forceConsistentCasingInFileNames`, with ES2023/NodeNext module resolution. Module syntax/extensions MUST follow actual build/runtime configuration, not an invented universal extension convention; React runtime imports MUST match JSX configuration.
6. Clear local types MUST be inferred. Public methods and permitted exported functions MUST declare return types. Untrusted values MUST enter as `unknown` and be narrowed/validated. Routine `any`, unchecked assertions, non-null assertions, and `@ts-ignore` MUST NOT be used. Unavoidable interop exceptions MUST be narrow, justified, and preserve surrounding contracts. Finite scalar choices MUST use string-literal unions, not enums.
7. Type-only imports MUST use `import type`. Source files MUST have at most one primary named export (entries MAY have none), with only supporting interfaces needed to describe/consume it as additional exports. Supporting aliases and unrelated interfaces MUST have their own files; private helpers/types MUST remain unexported. Default exports MUST be limited to externally mandated conventions.
8. `.stories.tsx` MAY export default Storybook metadata and multiple named stories, but no unrelated exports or production barrels. A library's curated package-root `index.ts` is the sole barrel/multiple-public-export exception. All other barrels and convenience re-exports, including nested/application `index.ts`, MUST NOT exist. Public application capability APIs MUST be explicitly identified single-export files.
9. Intra-package imports MUST be relative, including public cross-capability files. Inter-package imports MUST use the supplying package's public root, never relative traversal, deep imports, or public subpaths. TypeScript path aliases/equivalent internal import aliases MUST NOT be used; ordinary package names and type declarations are not aliases.
10. Classes, methods, interfaces, named type aliases, and permitted standalone functions MUST have JSDoc describing purpose and applicable inputs, outcomes, failures, mutation, and lifecycle obligations, not merely repeating names. Inline comments MUST explain non-obvious reasons/constraints, not narrate code.
