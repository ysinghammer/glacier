# 0002 — Technology and dependencies

1. Project-authored application, service, library, and test code MUST use TypeScript. Server-side TypeScript and workspace tooling MUST use active Node.js LTS; package management MUST use pnpm and local/CI workspace tasks MUST use Turborepo. Linting MUST use Oxlint; formatting MUST use Oxfmt. Current exact configuration pins are Node `24.21.0` in `.node-version`, `.nvmrc`, and manifests, and pnpm `11.9.0` in `package.json`; these pins implement, not replace, the active-LTS standard. `pnpm-workspace.yaml` discovers `packages/apps/*`, `packages/services/*`, and `packages/libraries/*` with strict engines, without requiring placeholder products.
2. Deployable backend services MUST be Docker images. Local development MAY run outside Docker except where tests require containers. Frontend applications MUST use React built with Vite. Services needing relational persistence MUST use PostgreSQL, Drizzle ORM access, and Drizzle Kit migrations; services needing shared caching MUST use Redis. These needs MUST NOT be manufactured for services without them.
3. Snyk MUST perform dependency and applicable container-image security scans; Renovate MUST propose automated dependency updates. Both MUST be GitHub integrations, not direct npm dependencies. Node, pnpm, Docker, and GitHub Actions are platform/workspace choices, not prescribed npm dependencies.
4. Every NEW direct runtime/development dependency MUST receive explicit approval before addition, including listed packages; approval MUST remain within its listed scope. Transitively supplied dependencies of approved direct dependencies require no separate approval. Unlisted framework, HTTP/validation, hosting, styling/routing, and other product-dependent choices remain unspecified, not prohibited; this policy does not newly prescribe or restrict those choices. Any new direct runtime/development dependency still MUST receive explicit approval before addition. Current versions normally belong in manifests, not a blanket permission to upgrade.

5. Root commitlint configuration MUST use Conventional Commits header rules with exactly one scope, `workspace` or a workspace package directory name minus `glacier-`, derived from `pnpm-workspace.yaml`. Root Husky `commit-msg` MUST run `pnpm exec commitlint --edit "$1"`; CI MUST check each PR commit independently against the root configuration. This bounded tooling contract does not migrate or authorize commit workflow.
6. `@glacier/reflection` MUST remain technology-neutral, native ESM, ES2023, root-only generated `dist/index.js`/`dist/index.d.ts`, with no runtime dependencies or CommonJS/public-subpath entry. Its package-local development pins are `vitest`, `@vitest/coverage-v8`, `@vitest/browser-playwright` exactly `5.0.3`, `playwright` exactly `1.63.0`, and Vite exactly `8.3.2`; shared TypeScript/Node tooling remains workspace-owned. The user's 2026-10-04 Vite approval is solely for its existing independent non-React distribution side-effect-retention bundle, not production compilation or runtime Vite. It MUST NOT imply approval of DI, reflect-metadata, schema validation, React, another bundler, or React-only testing packages. Runtime verification bounds are Node 24 LTS (workspace `24.21.0`) and pinned Playwright Chromium, not other browsers/historical compatibility or npm publication.
7. Reflection runtime root imports intentionally activate only `Reflect.metadata`, retained with `sideEffects: true`; type-only imports do not activate it. Consumers MUST import before legacy decorated declarations execute and enable `experimentalDecorators`/`emitDecoratorMetadata` for compiler records. Modern standard decorators and recovery of missed emissions are unsupported. Activation MUST NOT start resources, background work, registries, or consumer instances or install the general reflect-metadata API.
8. Foreign metadata handlers and duplicate physical package copies MUST fail without replacing descriptors or invoking foreign accessors. Recovery MUST correct imports/dependencies and restart the process/browser realm, not delete handlers or use unsupported reset/uninstall/toggle operations. Compiler representations are bounded functions/classes or `undefined`, not reconstructed interfaces, generic arguments, parameter names, declaration kinds, signature equivalence, or usable dependency constructors. Explicit typed-symbol annotations MAY supply erased interface identity; retrieval is not DI resolution or consumer construction. These contracts MUST NOT broaden other libraries' scopes.
