# 0008 — React

1. React components MUST be function components, not classes or `React.FC`. Components accepting props MUST declare explicit `I...Props` interfaces. A context definition and its provider MUST be separate files; general single-export and supporting-interface rules apply.
2. Components with side effects or state access not entirely self-managed MUST split into a smart component and a separate dumb rendering component in distinct files. External access includes context, shared stores, router state, and subscriptions, even without `useEffect`. Side effects include external I/O, timers, subscriptions, and imperative browser/DOM work (including focus/measurement), whether in effects or event handlers.
3. Smart components MUST own external integration directly or through hooks and supply explicit props for all externally sourced rendering values, applicable loading/empty/error states, and interaction callbacks. Dumb components MUST render from resolved props and fully owned local UI state, not clients, stores, or integration handles. They MUST NOT perform external side effects/access external state through hooks/helpers. They MAY calculate pure derived values, manage entirely local UI state, use pure/local-state hooks, and invoke supplied callbacks. Parent-supplied props are permitted, not prohibited external access.
4. Components without external access/side effects MUST NOT require artificial smart wrappers. Extracting a hook MUST NOT substitute for the component split. Connected components coordinate presentation, not a replacement application layer.
5. React callers MUST NOT move domain rules or application orchestration into components/hooks; hooks MUST NOT contain use cases or concrete external clients. This includes integration hidden in rendering helpers rather than appropriate outbound adapters.
6. Hooks MUST be unconditional at the top level of components/custom hooks. Props/state MUST NOT be mutated. State MUST contain the minimum source of truth; derived values MUST be calculated while rendering, not duplicated in state.
7. Effects MUST synchronize external systems, not derive state or replace handlers. Dependencies MUST reflect used reactive values; dependency rules MUST NOT be suppressed to force scheduling. Subscriptions/resources MUST be cleaned up; asynchronous completion MUST prevent stale results from overwriting current state or updating obsolete consumers.
8. `useMemo`, `useCallback`, and `memo` MUST address an identified performance/identity need, not be defaults. Lists MUST use stable identity-based keys, not rendering-generated keys or array positions when identity/order can change.
9. UI MUST use semantic HTML/native controls where appropriate, accessible control names, input labels, keyboard operation, and visible focus. ARIA MUST supplement, not replace, suitable native semantics.
10. Data-dependent UI MUST explicitly represent applicable loading, empty, and error states. User errors MUST be actionable and secret-safe, retaining expected-rejection/exception distinctions. These conventions prescribe neither a styling/router dependency nor a visual design system.

Provenance: ADR-0004; React Rules; Frontend Application/Library Rules.
